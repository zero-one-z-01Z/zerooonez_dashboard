# دليل Web Builder v2

يبني Web Builder **عقد الصفحة** أولًا، ثم يعرض الأثر المتوقع قبل أي كتابة. لا يعني تنزيل JSON أو ظهور زر أو Modal أن عملية الأعمال أو الملفات أو العلاقات المعقدة أصبحت عاملة؛ ذلك يحتاج حزمة Agent وتنفيذًا واختبارًا فعليين.

## Quick brief (English)

Define route, controller, model, permissions, table, create/edit forms, filters, actions, modals and sidebar in one v2 JSON contract. Preview first. Direct mode may generate only the supported simple resource. Agent-required mode never generates partial code: download its JSON and Markdown handoff and give both to Codex. The Builder does not start an Agent and does not create a Skill.

## قبل البدء

- يلزم PHP المتوافق مع Composer (التحقق هنا على 8.4)، و`APP_ENV=local` و`DASHBOARD_BUILDER_ENABLED=true`. الوصول من `127.0.0.1` أو `::1` فقط، مع جلسة Admin؛ الأداة غير متاحة للإنتاج. إذا كان config cache مفعّلًا، حدّثه بعد تعديل الإعدادات بالطريقة المعتادة للمشروع.
- افتح `/admin/dashboard-builder` بحساب Admin.
- اختر Model موجودًا ثم اضغط «فحص Model والمسارات». هذه قراءة metadata فقط؛ لا تعيد سجلات أو أسرارًا للمتصفح.
- إن كان Model أو Schema غير قابلين للتحقق، أكمل الوصف. ستنتج المعاينة مسار Agent بدل افتراض علاقة أو عمود.
- عند كتابة مفتاح ترجمة للحقل أو العمود، يملأ Builder القيمتين الفارغتين من الملف الموجود: المفتاح غير المسبوق يعني `inputs.key`، ويمكن كتابة `admin.key` أو `inputs.key` صراحة. لا يستبدل ما كتبته يدويًا، وينبّهك للغة الناقصة أو لتعارض القيمة قبل التوليد.

## الخطوات الثماني

1. **التعريف:** اكتب `resource` وController وModel ومفتاح الصلاحية والعنوانين. الراوت المرجعي هو `/admin/{resource}`؛ لا يثق الحفظ في `id` مخفي لتحديد السجل.
2. **العمليات:** فعّل الإضافة والتعديل والحذف والحذف الجماعي والتصدير والفلاتر والعرض. الحذف الجماعي لا يصح من دون حذف فردي.
3. **الجدول والفلاتر:** أنشئ الأعمدة بالترتيب، ثم عرّف الفلاتر منفصلة مع `target` و`equals|contains` و`audience`. لا تتحول الوسائط أو Multiform أو الخريطة إلى فلتر تلقائيًا.
4. **الإضافة:** أضف الحقول بالترتيب. افصل دائمًا اسم الطلب (`name`) وعمود التخزين (`column`) ونوع الواجهة (`input`) والعلاقة (`relation`) ومسار قراءة التعديل (`read_path`). اختيار لغة البيانات `both` يوسع الاسم والعمود ومفتاح الترجمة مرة واحدة؛ مثل `demo_category_name` إلى `demo_category_name_ar` و`demo_category_name_en`، وتظهر التسميتان بوضوح كـ«(عربي)/(إنجليزي)» و`(Arabic)/(English)`.
5. **التعديل:** اتركه `same` لاستعمال حقول الإضافة وإضافة `id` مخفي للعرض فقط، أو اختر `custom` لتعريف مستقل. الحقول read-only والمشتقة و`empty` لا تدخل الحفظ.
6. **الأكشنات والمودالات:** استخدم «اختر قالبًا» أولًا: تعديل، حذف، عرض، أو مودال عام. التعديل والحذف يملآن الـRoute والصلاحية والمعالج و`#edit_modal/#edit_form` تلقائيًا ولا يتكرران. العرض يحفظ الرابط المعتاد فقط ويظهر في المعاينة كـ«رابط يحتاج استكمال»؛ يظل مخفيًا من الجدول حتى توجد صفحة تفاصيل فعلية. المودال العام ينشئ الزر والمودال بمعرّفات متوافقة. يمكن تعديل البيانات أو إضافة شروط `if` (AND)، لكن العملية الخاصة أو شرط أعمال يمر إلى Agent. لا توجد خانة JavaScript حر.
7. **Sidebar والترجمات:** اختر root أو sub أو hidden، ثم المجموعة والأيقونة والترتيب. المجموعة الجديدة تكتب ترجمتها العربية والإنجليزية في `admin`.
8. **المراجعة:** راجع العقود، الشكل الدلالي للنموذج، الملفات والـDiff والبصمة والخطوات التالية قبل الضغط على الإنشاء.

## أنواع الحقول

| مجموعة | الأنواع | ما يلزم وصفه |
| --- | --- | --- |
| مباشر | `text`, `textarea`, `switch`, `hidden`, `empty` | التخزين والتحقق واللغة وHTML type عند النص. `empty` فاصل فقط بلا اسم أو عمود. |
| اختيار | `single`, `multi_select` | خيارات ثابتة بقيمتي `text_ar/text_en` أو Route وعلاقة. الافتراضي واحد فقط في `single`. |
| وسائط ومحتوى | `image`, `file`, `upload_images`, `image_preview`, `html` | disk/directory والأنواع والحجم؛ حد الصور للمنتجات 14 وحجم المثال **2 MB**. |
| جغرافي | `map`, `boundary` | حقول الإحداثيات أو `[[lat,lng], ...]` ومسار القراءة. الصفر إحداثي صحيح. |
| مركب | `multiform`, `permissions` | أبناء الصفوف وحدودها أو عقد مجموعات الصلاحيات. |

العلاقات المتسلسلة تسجل `parent_id`, `child_id`, `parent_key`, `child_key` لكل ارتباط. داخل Multiform تبقى العلاقة ضمن الصف نفسه. `multi_select` يحدد `pivot` أو `json` صراحة؛ التفريغ الصريح غير غياب الحقل في update.

## مباشر أم Agent

التوليد المباشر محصور في حقول scalar البسيطة، `single` الثابت، وعلاقة `belongsTo` كاملة وبسيطة، مع اختصاري التعديل والحذف القياسيين. أما chains و`multi_select` والعلاقات غير المكتملة والوسائط والخرائط والحدود وHTML وMultiform والصلاحيات وصفحة التفاصيل الفعلية والمودالات/الأكشنات الخاصة والـcustom page وقواعد الأعمال فتظهر كـ **«جاهزة للتنفيذ بواسطة Agent»**.

في هذا الوضع:

1. لا تضغط «إنشاء الملفات»: الزر معطل عمدًا.
2. نزّل JSON وMarkdown من «تنزيل حزمة Agent».
3. أرسل الملفين داخل Codex مع وصف البيانات الفعلية والعلاقات وقواعد العمل.
4. بعد تنفيذ Agent، اختبر `get_single_item` والحفظ والصلاحيات والوسائط أو الأبناء في الصفحة المنفذة نفسها.

لا يبدأ التنزيل Agent تلقائيًا، ولا ينشئ Skill في هذه المرحلة.

## الاستيراد والتصدير

زر التصدير ينتج `schema_version: 2`. الاستيراد يقبل v2 أو تعريف v1 البسيط ويطبّعه إلى v2؛ راجع الحقول والعناوين بعد الاستيراد قبل المعاينة. JSON المتقدم وسيلة مراجعة اختيارية، وليس بديلًا عن تحرير الحقول المنظمة في الواجهة.

المعاينة لا تكتب. التوليد يرسل فقط `definition` التي عُرضت مع `fingerprint`. أي تعديل بعد المعاينة يبطلها، وأي تغيّر للملف المشترك بين المعاينة والكتابة يرفض المحاولة بدل الكتابة فوق عمل آخر.

## بعد التوليد المباشر

1. راجع الملفات التي أُنشئت ونسخ الملفات المشتركة في `storage/app/dashboard-builder-backups/`.
2. شغّل Migration المحددة في المعاينة فقط عند الحاجة، ثم `php artisan dashboard:sync-permissions resource_name`؛ تشغيل الأمر مرة أخرى يضيف المفقود فقط.
3. امنح الدور الصلاحيات المطلوبة يدويًا من إدارة الصلاحيات؛ الأمر لا يمنح أدوارًا.
4. افتح رابط الصفحة الذي أعادته المعاينة وجرّب الإضافة والتعديل بالعربية والإنجليزية. لا تُعد توليد المورد نفسه فوق تخصيصاته؛ سلّم التغيير إلى Agent.

## ما اختُبر وما يحتاج تنفيذ الصفحة نفسها

راجع [تقرير التحقق v2](BUILDER-V2-VERIFICATION.md). اختبارات الويب تجمع المواصفات وتعرضها وتولّد الصفحة البسيطة في بيئة معزولة. حفظ الأبناء/pivot/صور المنتجات والنشر والخدمات الخاصة لا ينفذ تلقائيًا؛ نجاح تصدير هذه الحزم لا يُعد نجاحًا لاختبارات حفظها. خرائط الخدمات الخارجية لم تُختبر بحساب أو API key حي.

فُحصت هذه التعريفات في PHP 8.4 عبر `ResourceDefinitionV2::normalize` ثم `ScaffoldGeneratorV2::preview` مع جذر مؤقت يحتوي routes/lang فقط، بلا قاعدة بيانات حية وبلا `generate`: الستة المركبة أعادت `agent_required` (3، 5، 8، 4، 5، 14 أسبابًا بالترتيب الظاهر في الجدول عدا simple)، و`simple` أعاد `direct` مع 9 تغييرات. هذا يثبت صحة العقد ومسار المعاينة فقط، وليس تنفيذ العلاقات أو الحفظ في قاعدة بيانات.

## فحص القبول بعد التنفيذ

- افحص العربية والإنجليزية على desktop و390px، والتبديل بين سجلي تعديل متتاليين.
- افحص تحميل السجل: علاقات غائبة، `read_path`، اختيارات متعددة بأسمائها، وصور/أبناء السجل نفسه فقط.
- افحص الحفظ: صلاحية السيرفر، route id، روابط pivot، تفريغ صريح، ملكية الوسائط والأبناء، rollback عند الفشل.
- شغّل `php artisan dashboard:sync-permissions {resource?}` مرتين؛ ينشئ الناقص فقط ولا يمنح أدوارًا تلقائيًا.
