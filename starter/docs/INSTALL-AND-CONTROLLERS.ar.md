# استخدام الداشبورد بعد التثبيت

## حالة هذه النسخة

هذه نسخة المصدر المحلية تحت الاختبار، وليست إصدارًا جديدًا منشورًا على GitHub.
المشروع مرتبط بمجلد الباكدج المحلي عبر Composer path repository؛ لا تستخدم هذا المسار المطلق في الإنتاج.

ملفات التشغيل أصبحت داخل مشروع Laravel. الباكدج هي أداة تثبيت وتحديث، وليست المكان الذي تعدل فيه صفحات مشروعك.

## الدخول لأول مرة

من جذر المشروع، استبدل البيانات المثال ببياناتك:

```bash
php artisan dashboard:create-admin "اسمك" "you@example.com" "رقمك"
```

سيطلب كلمة المرور بشكل مخفي. لا يوجد حساب أو كلمة مرور افتراضية.
شغّل المشروع وافتح /admin/login، ثم /admin/dashboard-builder بعد الدخول.

يتطلب الـBuilder بيئة APP_ENV=local وDASHBOARD_BUILDER_ENABLED=true واتصالًا من 127.0.0.1 أو ::1.
بعد تعديل .env شغّل php artisan config:clear.

## إنشاء صفحة كاملة بالـBuilder

1. اكتب اسم المورد مثل cities، والموديل City، والكنترولر CityController، ومفتاح الصلاحية city.
2. اكتب عنوان الصفحة بالعربية والإنجليزية، واختر إنشاء Model جديد لو لم يكن موجودًا.
3. اختر الإضافة والتعديل والحذف، ثم عرّف أعمدة الجدول.
4. عرّف الحقول؛ استخدم both للنص العربي والإنجليزي، واجعل أعمدة الجدول تشير لحقول فعلية مثل name_ar وname_en.
5. اختر التعديل مطابقًا للإضافة أو عرّفه مستقلاً، ثم الأكشنات والـSidebar.
6. راجع المعاينة واضغط إنشاء فقط إذا كانت الحالة تدعم التوليد المباشر.
7. نفّذ الأوامر التي تعرضها النتيجة؛ لمثال cities:

```bash
php artisan migrate
php artisan dashboard:sync-permissions cities
php artisan route:clear
```

اسم المورد بعد sync-permissions هو مفتاح JSON مثل cities، وليس اسم الكلاس City.
لا تشغّل الأمر قبل إنشاء تعريف المورد. الحالات المركبة تصدّر حزمة تنفيذ ولا تعني أن الصفحة أصبحت عاملة.

## أماكن الملفات التي تعدل فيها

- كنترولرات الأساس: app/Http/Controllers/Admin/
- الكنترولرات المولدة: app/Http/Controllers/Admin/Generated/
- الموديلات: app/Models/
- الراوتات الأساسية: routes/admin.php
- بعض تعريفات v1 القديمة: routes/admin-generated/
- تعريف الصفحة: dashboard/resources/{resource}.json
- القالب: resources/views/dashboard/
- JavaScript: resources/js/back/
- الترجمة: resources/lang/ar/ وresources/lang/en/
- ملفات المتصفح المبنية: public/dashboard/
- الوظائف المشتركة المحلية: app/Dashboard/

الكنترولر المولد يستخدم دوال مثل inputs_list وshow_list وstore عبر كود مشترك محلي تحت app/Dashboard.
تعديل تعريف صفحة مولدة موجودة لا يكون بإعادة التوليد فوقها؛ حافظ على تخصيصاتها وعدّل ملفاتها.

## كنترولر فارغ فقط

```bash
php artisan make:controller Admin/CategoryController
```

هذا ينشئ كلاسًا فقط؛ لا يضيف موديلًا أو حقولًا أو راوتًا أو صلاحيات أو Sidebar.

## تعديل JavaScript والتحديث

بعد تعديل JS داخل المشروع، ابنِ الملفات محليًا:

```bash
npm exec vite -- --config vite.dashboard.config.js
```

مالك الباكدج يعدل مصدرها ثم يبنيها:

```bash
npm run build
npm run build:starter
```

في المشروع المستهلك، لمراجعة تحديث الملفات ثم تطبيقه:

```bash
php artisan dashboard:update --dry-run
php artisan dashboard:update
```

تحديث Composer وحده لا ينسخ المصادر الجديدة إلى مشروعك.
بعد نشر إصدار مستقر واستخدامه بدل المسار المحلي، حدّث إصدار Composer أولًا ثم شغّل أمر تحديث الملفات.
التعديلات المحلية المتعارضة تُحفظ ويُبلّغ عنها. لا تستخدم --force دون مراجعة ونسخة احتياطية.
لا تعدل vendor؛ كود صفحاتك وقالبك داخل المشروع.

## حدود التحقق

اختبارات المشروع المعزول تتحقق من الدخول والصلاحيات الأساسية والحفظ وتوليد City.
إرسال بريد الاستعادة الخارجي يحتاج إعداد بريد المشروع واختبار تسليم فعلي؛ اختبارات البريد المعزولة لا تثبت وصول الرسالة.
نفس قالب الداشبورد مستخدم، بينما الهوم يعرض بيانات الإدارة المتاحة؛ إحصاءات المزادات لا تُنشأ في مشروع لا يملك جداول المزادات.
