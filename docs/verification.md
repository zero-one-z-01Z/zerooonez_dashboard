اختبار Chrome يستخدم Blade وJavaScript ومكتبات الواجهة الفعلية مع Backend محاكى، لذلك يثبت دورة التابات والمودالات ولا يثبت اتصال قاعدة الإنتاج أو الخدمات الخارجية.

التحقق بتاريخ 8 سبتمبر 2026 على نسخة معزولة من المشروع، باستخدام PHP 8.4.4 وNode 22.14.0 وLaravel 12.47.0 وVite 6.4.1. لم يتم تغيير إصدارات Composer أو NPM في ملفات القفل.

الاختبارات الجديدة تستخدم ملفات PHP مولّدة فعليًا، وتشغّل Migration لجدول الاختبار داخل SQLite في الذاكرة، ثم تنفذ طلبات إضافة وقراءة وتعديل وحذف. تشمل تحقق الحقول، المعرّف الموجود بالمسار، نطاق الحقول المعروضة، أنواع البيانات، المعاملات، صلاحيات غير المدير العام، ومحاولات التوليد المتعارضة.

اختبارات محرر الأدوار تفتح القالب الحقيقي، وتختار الصلاحيات الجديدة وتحفظها وتعيد قراءتها، بما في ذلك إلغاء اختيار صلاحية. الاختبارات لا تتصل بقاعدة بيانات المشروع أو بريد أو خدمات خارجية.

اختبار المقارنة يستخدم الكنترولرز الفعلية مع بدائل محدودة لإطار العمل والاستعلامات، ويفصل السجل المولّد عن بيانات الصفحات الأصلية. يثبت تطابق العقود المحددة، ولا يثبت نتيجة SQL لكل العمليات أو تكامل الخدمات الخارجية.

اختبارات Node تستخدم بدائل DOM وjQuery محدودة؛ فُحصت واجهة المولّد نفسها في متصفح حقيقي، لكن لم يتم تنفيذ كل عمليات القالب القديم أو الخرائط أو رفع الملفات في المتصفح.

## إصلاحات ظهرت أثناء الربط

- تحميل صفحة الجدول والتبويبات ينتظر الاستيرادات الفعلية؛ لا دوال جاهزية وهمية أو اعتماد على سباق تحميل Vite.
- فصل تحقق نماذج الإضافة والتعديل والنوافذ المخصصة، ومسح فلاتر تبويب سابق عند الانتقال.
- إلغاء طلب التبويب القديم عندما يختار المستخدم تبويبًا آخر، مع إبقاء الجدول الحالي عند فشل الطلب الجديد.
- منع إرسال طلبين عند تغيير مفتاح مخصص، وإزالة الاعتماد على event/$obj غير الممررين.
- إزالة تنبيه تشخيصي من نطاق التاريخ، وتصحيح populateForm لاستخدام data.id.
- نصوص الخلايا وعناوين التبويبات تُعرض كنص؛ يبقى النوع الصريح html_text للمحتوى المنسق.
- أخطاء طلبات admin تستخدم عقد Laravel: errors مع 422، و403 للصلاحيات، و419 لـCSRF؛ عقد API السابق بقي كما هو.
- الحقول المعرّفة في المورد تُعرض حتى إن كانت مخفية في موديل الـAPI، دون كشف حقول أخرى؛ وتواريخ النماذج لها الصيغة المناسبة.
- أسماء الحقول المولّدة مثل image/lat/permissions تتبع نوع الحقل المعلن، مع إبقاء معالجات الصفحات القديمة عند غياب هذا التعريف.

## حدود البيئة الأصلية

المصدر المرسل لم يحتوِ `.env` أو `vendor` أو `public/dashboard`. تم تثبيت dependencies في نسخة العمل للاختبار، وتجهيز حساب وقاعدة SQLite مؤقتين لاختبار واجهة المولّد فقط. لم تُستخدم بيانات أو حسابات إنتاج، ولم تُشغّل migrations على قاعدة فعلية.

صفحة home تعتمد جداول العمل غير الموجودة في قاعدة المعاينة الصغيرة؛ لذلك لا يُعد نجاح واجهة المولّد اختبارًا لكل بيانات الصفحة الرئيسية. كذلك توجد دوال رسوم قديمة تستدعي مسارات غير موجودة في نسخة routes المرسلة؛ راجع دليل `home/README.md` عند تجهيز تلك الإحصاءات.

اختبار Laravel التجريبي القديم `tests/Feature/ExampleTest.php` ليس جزءًا من نتائج الاختبارات الجديدة: يتوقع 200 من `/` بينما المسار الحالي يحوّل إلى admin.home، كما يحتاج JWT configuration. لم يتم تغيير المسار أو اختبار العينة لإخفاء هذا الاختلاف.

ملفات مثال المتصفح الستة حُفظت كدليل تجريبي خارج مصدر التطبيق ثم أزيلت من نسخة العمل؛ لا توجد صفحة منتجات تجريبية أو Migration مثال مفعّلة ضمن التسليم. يوجد تعريف مثال فقط في `dashboard/examples/product.json`.
